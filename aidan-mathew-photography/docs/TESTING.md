# Testing

This file records what was actually tested, how, and what still has to be checked on your own Supabase project, hosting and devices. Nothing here claims more than was run.

## Automated tests that passed during development

| Suite | Command | Result |
|---|---|---|
| Type check (web) | `npm run typecheck` | No errors |
| Type check (worker) | `cd worker && npm run typecheck` | No errors |
| Production build | `npm run build` | Succeeded; all 37 routes built |
| Unit tests | `npm test` | 47 passed |
| Database behaviour | `scripts/test-db.sh` on PostgreSQL 16 with Supabase stand-ins | All 8 checks passed |
| Worker pipeline | `cd worker && npm run selftest` with FFmpeg 6.1 | All 14 checks passed |
| Route smoke test | Production server, no Supabase configured | Every public route returned 200; unknown story and film slugs returned 404; /admin redirected to login |

### What the database tests prove

- Visitors can read only published views. They get permission errors on bookings and media tables, and cannot insert reviews.
- Visitors see the published page, not the newer draft.
- Unpublished media isn't public, and the private notification email isn't exposed.
- A signed-in non-admin can't read bookings or drafts, confirm a booking, or make themselves an admin.
- Booking stages can't be skipped. A second confirmation on a full date is refused. Blocked dates can't be confirmed.
- **Two simultaneous confirmations for the same date: exactly one succeeds.**
- A pending request doesn't make a date unavailable.
- Review text can't be edited.
- Story sections are replaced atomically and keep their order.
- Rate limiting cuts off at the limit. A processing job can be claimed by only one worker. Retention can't be set below 30 days.

### What the worker self-test proves

It uses real clips generated by FFmpeg and runs the same code the worker runs.

- 9 s and 16 s videos are rejected with "Please upload a video between 10 and 15 seconds long."
- 10, 12 and 15 s MP4s, an 11 s MOV and a 13 s WebM are accepted.
- A text file renamed `.mp4`, and a photo uploaded as a video, are rejected by content.
- A photo that is too small is rejected.
- Portrait video keeps its shape (720×1280 and 1080×1920 versions).
- Photos produce 480/960/1600/2400px WebP versions.

## Not yet tested — do these on a staging Supabase project

These depend on real accounts and devices and could not be run in the build environment:

1. Resumable upload through Supabase Storage. Upload a large video, disconnect Wi-Fi midway, reconnect and press Retry: it should continue rather than restart.
2. The full flow end to end: upload → Validating → Processing → Ready → Publish → visible on the site → Unpublish → gone, with the public file URL returning an error.
3. Supabase-specific behaviour of the storage policies and the cross-bucket copy used by Publish.
4. Email delivery through Resend, and the retry button after a failure.
5. Visual review of the design in real browsers, at phone, tablet and desktop widths.
6. **Accessibility.** The build includes semantic headings, labelled fields, visible focus, skip links, keyboard-operable menus, a lightbox dialog, manual carousel controls, reduced-motion support and a hero pause control. It has **not** been audited with automated tools (axe, Lighthouse) or with screen readers (VoiceOver, NVDA), and colour contrast was checked by calculation only. WCAG 2.2 AA is the target, not a verified claim.
7. Hero video autoplay on iOS Low Power Mode. It should fall back to the poster image, and the pause button should work.

## Running the tests yourself

```bash
npm ci && npm run typecheck && npm test && npm run build
cd worker && npm ci && npm run selftest          # needs ffmpeg and ffprobe on PATH
# Database tests need an EMPTY local PostgreSQL database (never your Supabase project):
createdb amp_test && DATABASE_URL=postgresql:///amp_test scripts/test-db.sh
```
